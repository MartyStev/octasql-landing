## 1. Динамическое маскирование и анонимизация ПДн (PII Masking & Vault)

### 🎯 Бизнес-цель
Обеспечить 100% соответствие требованиям **152-ФЗ (РФ)**, **GDPR (ЕС)**, **HIPAA (США)** и **PCI-DSS**. Гарантировать, что ни один байт чувствительных персональных данных (ПДн) и банковской тайны не попадет в окно контекста LLM, внешние облака или в незашифрованные логи.

### 🏗 Архитектура решения
```
[ Исходная СУБД ] ──► [ PII Detection Scanner ] ──► [ In-Flight Tokenizer ] ──► [ LLM / Agent ]
                                                            │                   (Видит только токены:
                                                            ▼                   `anon_user_8f91`)
                                                 [ Local Secure Vault ]
                                                 (Обратный маппинг в памяти)
```

### ⚙️ Ключевые компоненты:
1. **Автоматический PII-Детектор на этапе 1-Pass интроспекции**:
   - Анализ DDL, имен колонок и DDL-комментариев (`email`, `phone`, `passport`, `snils`, `inn`, `card_number`, `client_name`).
   - Паттерн-матчинг по регулярным выражениям и легковесным NER-моделям (Named Entity Recognition) на выборках значений без их выгрузки.
2. **In-Flight Tokenization & Pseudonymization Engine**:
   - Замена реальных идентификаторов на криптографические детерминированные псевдо-токены (HMAC-SHA256) в оперативной памяти:
     - `Иванов Иван Иванович` $\rightarrow$ `Client_Token_98A1`
     - `+7 (999) 123-45-67` $\rightarrow$ `+7 (XXX) XXX-45-67` (частичное маскирование)
     - `4276 3800 1234 5678` $\rightarrow$ `4276 **** **** 5678`
3. **Zero-Knowledge LLM Context**:
   - Модель оперирует исключительно анонимизированными агрегатами и псевдо-токенами.
   - Обратный маппинг выполняется локальным движком непосредственно перед отображением авторизованному аналитику с соответствующим уровнем доступа.

## 2. Дифференциальная приватность (Differential Privacy)

### 🎯 Бизнес-цель
Защита от косвенной деанонимизации сотрудников и клиентов при выполнении агрегирующих аналитических запросов на малых выборках.

### ⚙️ Технические механизмы:
1. **K-Anonymity & L-Diversity Enforcer**:
   - Автоматическая блокировка или объединение когорт, размер которых меньше заданного порога безопасности ($K < 5$).
2. **Laplacian / Gaussian Noise Injection**:
   - Добавление математически калиброванного статистического шума (Laplace Mechanism) к агрегатным функциям `COUNT`, `SUM`, `AVG`, исключающего возможность вычисления единичного значения конкретного лица методом исключения.

## 3. Гранулярный RBAC и Row/Column-Level Security

### 🎯 Бизнес-цель
Предотвратить доступ рядовых аналитиков и бизнес-пользователей к не предназначенным для их роли данным (например, финансовые данные зарплат топ-менеджмента или данные филиалов других регионов).

### ⚙️ Технические механизмы:
1. **Интеграция с корпоративными IdP**:
   - Поддержка протоколов **OIDC / OAuth2 / SAML 2.0** и синхронизация с **Active Directory, Keycloak, FreeIPA**.
2. **AST-Enforced Policy Injection**:
   - Динамическое внедрение фильтров на уровне компиляции абстрактного синтаксического дерева (AST) до отправки запроса в СУБД:
     ```sql
     -- Пользователь запросил: SELECT * FROM sales.deals
     -- Движок автоматически модифицирует AST:
     SELECT * FROM sales.deals 
     WHERE region_id IN (SELECT allowed_region FROM security.user_permissions WHERE user_id = :current_user_id)
       AND deal_amount < 10000000;
     ```
3. **Column-Level Masking**:
   - Автоматическая замена недоступных колонок на `NULL` или хэш в зависимости от роли пользователя.

## 4. Неизменяемый криптографический аудит (SIEM Integration)

### 🎯 Бизнес-цель
Обеспечение требований ИБ-отделов и регуляторов по ведению журнала безопасности и расследованию инцидентов.

### ⚙️ Технические механизмы:
1. **Merkle-Tree Audit Log (Хэш-цепочка целостности)**:
   - Каждый выполненный запрос, сгенерированный SQL, использованный контекст и ответ подписываются криптографическим хэшем с привязкой к предыдущей записи (защита от подделки логов администратором).
2. **Streaming Telemetry в SIEM / SOC**:
   - Нативная потоковая отправка событий аудита в формате JSON / CEF / Syslog в системы:
     - **Splunk Enterprise**
     - **Elasticsearch / OpenSearch (ELK)**
     - **IBM QRadar / ArcSight**
     - **Kaspersky KUMA**

Предоставить бизнес-пользователям, руководителям и аналитикам удобный графический интерфейс для интерактивного исследования данных без использования терминала.

### ⚙️ Технические механизмы:
1. **Modern Frontend Stack**:
   - React 19 / Next.js / Tailwind CSS / shadcn/ui.
   - Интерактивный канвас гипотез (React Flow / Node Graph).
2. **Rich Visualizations**:
   - Автоматический подбор и рендеринг диаграмм (Apache ECharts / Plotly): воронки, тепловые карты корреляций, факторные диаграммы «Водопад» (Waterfall Charts).

## 6. Продвинутые аналитические ядра (Когорты, Воронки, Временные ряды)

### 🎯 Бизнес-цель
Расширить аналитический аппарат движка за пределы факторного анализа дельты, предоставив специализированные математические алгоритмы для Product & Growth аналитики.

### ⚙️ Технические механизмы:
1. **Cohort & Retention Kernel**:
   - Матрицы удержания (Day-N, Week-N, Month-N Retention, Rolling Retention, Churn Analysis).
2. **Funnel & Conversion Kernel**:
   - Многошаговый анализ конверсий пользовательских путей (User Journey / Drop-off Rate / Time-to-Convert).
3. **Time-Series Forecasting & Anomaly Detection**:
   - Автоматическое выявление сезонности, трендов и доверительных интервалов (Prophet / ARIMA / Holt-Winters) с детекцией выбросов на основе Z-Score и Isolation Forests.

## 7. Семантический векторный кэш (Semantic Query Cache)

### 🎯 Бизнес-цель
Снижение затрат на LLM-инференс еще на 40–70% при повторяющихся или схожих по смыслу вопросах разных пользователей компании.

### ⚙️ Технические механизмы:
1. **Векторная индексация запросов**:
   - Хранение эмбеддингов вопросов в Redis / Qdrant / PgVector.
2. **Cosine Similarity Matching**:
   - Если новый вопрос семантически эквивалентен ранее решенному ($Cosine \ge 0.96$), движок берет верифицированный план выполнения из кэша и только подставляет актуальные временные границы.

## 8. Мультимодальный Data Fabric (Таблицы + Документы/PDF)

### 🎯 Бизнес-цель
Объединение структурированных данных реляционных/колоночных СУБД с неструктурированными корпоративными документами (договоры, спецификации, протоколы встреч, транскрипты звонков).

### ⚙️ Технические механизмы:
1. **Unified Semantic Search**:
   - Совместный поиск по табличным агрегатам и выдержкам из PDF/Word документов.
2. **Hybrid RAG + SQL Planning**:
   - Например: *«Сопоставь фактические скидки в ClickHouse с максимальными скидками, зафиксированными в PDF-договорах с контрагентами»*.
